# Stack Status for DeskThing

🇮🇹 [Leggi in italiano](README.it.md)

A [DeskThing](https://deskthing.app) app for the Spotify **Car Thing** that watches your
[Komodo](https://komo.do) stacks (two Komodo Core instances) and **Home Assistant**, in a terminal-style
layout. Stopped services are pinned on top in red; the healthy ones scroll slowly underneath.

| All good | A stack is down |
|---|---|
| ![All stacks running, Rackbot walking](docs/ok.jpg) | ![Stopped stack pinned in red, Rackbot down and glitching](docs/alarm.jpg) |

*Screenshots at the Car Thing resolution (800×480), with sample data.*

A pixel-art mascot, **Rackbot**, walks along the bottom of the screen. When something breaks it
trips, falls over… and the screen **glitches**.

- `[ OK ]` / `[WARN]` / `[FAIL]` lines for every stack, with the number of services.
- A Komodo Core that does not answer is itself an alarm (no blind spot, unlike a monitoring
  service that can go down too).
- New alarms: the Car Thing screen wakes up, the display shakes, and — with
  [Pi Status](https://github.com/franzo-ux/deskthing-pi-status) on screen — the Car Thing switches here.
- "Test alarm" switch in the settings to try the whole chain safely.
- **English or Italian**: pick the language in the settings.

## Requirements

- A Car Thing flashed for DeskThing, connected to a PC running **DeskThing ≥ 0.11**.
- **Node.js ≥ 20** on the PC (only to build the app).
- One or two **Komodo Core** instances reachable from the PC, and an **API key** for each.

## 1. Komodo API keys (read-only)

On **each** Komodo Core:

1. **Settings → Users** → create a **Service User** (e.g. `deskthing`).
2. Give it **Read** permission on **Servers** and **Stacks** (directly or through a user group).
   Without it, Komodo answers with empty lists and the app shows `stack none visible (permissions?)`.
3. On that user: **API Keys → New API Key** and copy **key** and **secret** (the secret is shown once).

Never put the keys in the code or in this repository: they go in the DeskThing settings.

## 2. Build and install

```bash
npm install
npm run build          # → dist/homelab
# close DeskThing (tray icon → Quit), then:
npm run deploy         # copies the app into DeskThing and registers it
```

Start DeskThing and fill in the app settings. To update later: `npm run build`,
`npm run deploy -- --files`, restart DeskThing.

## 3. Settings (DeskThing → Apps → Stack Status)

| Setting | Meaning |
|---|---|
| Language | **English** (default) or **Italiano**: the screen switches at once, the setting labels after restarting DeskThing |
| komodo · URL / API key / API secret | first Komodo Core, e.g. `http://komodo-1.local:9120` |
| komodo-op · URL / API key / API secret | second Komodo Core |
| Home Assistant · URL | e.g. `http://homeassistant.local:8123` (only checks it answers) |
| Test alarm | turn it on to fire a test alarm, then turn it off |

The two Komodo slots are called `komodo` and `komodo-op` (setting keys); to use only one, leave the
other without keys (it shows as a warning, not as an alarm).
The app id is `homelab` (its first name): keep it if you fork, the other apps look for it.

## How it works

- The app server asks each Komodo Core `ListServers` and `ListStacks` every 15 s (read API,
  `X-Api-Key` / `X-Api-Secret`), and checks that Home Assistant answers.
- Stack states: `running` = OK; `deploying`, `restarting`, `created`, `paused`, `removing`, `unknown`
  = warning; anything else (`stopped`, `down`, `dead`, `unhealthy`, …) = failure.
- On a new failure it writes `apps/homelab/alert.json`: Pi Status and World Clock watch that file to
  show the alert and switch app (DeskThing 0.11's `sendToApp` is broken, see the Pi Status notes).
- Screen wake-up uses the screen-sleep script installed by Pi Status (no effect without it).

## Custom mascot

The client plays `app/client/mascot/walk_r0..7.png`, `walk_l0..7.png` (walking right/left) and
`fall0..5.png` (falling; the glitch starts on the last frame). Rackbot is generated by
`tools/rackbot_frames.py` (Pillow). To use your own character, replace those PNGs keeping the canvas
sizes (walk 42×76, fall 67×77) and anchors in `app/client/main.ts` (`WALK_*`, `FALL_*`).
Keep personal or third-party artwork out of a public fork.
